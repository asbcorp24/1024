Справка соответствует текущим index.html, app.js, admin.html и admin.js. Часть элементов интерфейса создаётся JavaScript динамически после загрузки страницы.

1. Быстрый запуск

  1. Включите КСК-1024 и подключите Ethernet к W5500.
  2. Посмотрите IP-адрес на OLED. При DHCP адрес выдаёт сеть; при STATIC используется сохранённый адрес.
  3. Откройте в браузере http://IP_ПРИБОРА/.
  4. В верхней панели проверьте модель, IP, LINK и версию прошивки.
  5. Подключите проверяемую кабельную сборку.
  6. Выберите эталон v3, заполните тип сборки, прибор и оператора.
  7. Нажмите «Запустить проверку».

Состояние теста поступает в браузер через SSE без перезагрузки страницы. Во время операции отображаются подготовка, измерение, анализ, сохранение, прогресс и длительность.

2. Обычная проверка кабеля

Обычная проверка не требует сервисного режима.

  1. В поле «Эталон» выберите совместимый файл v3.
  2. Введите «Тип сборки расчёта».
  3. Введите идентификатор в поле «Прибор проверки».
  4. Введите ФИО/номер в поле «Оператор проверки».
  5. Проверьте подсказку по жгутам и контактам под выбранным эталоном.
  6. Нажмите «Запустить проверку».

Тип сборки, прибор и оператор запоминаются браузером в локальном хранилище. При следующих проверках эти значения предлагаются автоматически.

Подсказка по раскладке

JavaScript строит 16 блоков по 64 физических канала. При наличии маркировки появляется легенда по жгутам. Нажатие на жгут выделяет его контакты; нажатие на строку связи или ошибки подсвечивает соответствующую пару.

Во время сканирования не отключайте и не переподключайте кабель. Изменение схемы во время теста приводит к ложным обрывам, паразитным связям или асимметрии.

Кнопка «Показать провода и маркировку» раскрывает номер провода, обозначения концов, локальные контакты и примечания из эталона.

Печать

После открытия результата JavaScript добавляет кнопку «Печать». Формируется отдельный протокол с итогом «ГОДЕН»/«НЕ ГОДЕН», реквизитами проверки, эталоном, сводкой ошибок и местами для подписей.

4. Экспорт CSV из конкретного отчёта

Кнопка «Экспорт CSV» в строке журнала конкретной проверки выгружает фактически измеренную схему соединений в формате, совместимом с импортом ручного эталона.

Колонки CSV:

Провод;Позиция;Маркировка;Контакт;Маркировка;Контакт;Примечание
КолонкаИсточник
ПроводМаркировка провода из эталона, если известна.
ПозицияСохраняется из примечания вида «позиция: ...», если такая позиция была импортирована ранее.
Маркировка / Контакт AЖгут/разъём и локальный контакт первого конца.
Маркировка / Контакт BЖгут/разъём и локальный контакт второго конца.
ПримечаниеИсходное примечание и, при наличии, признак паразитной связи или асимметрии.

Если у фактически найденного контакта нет логической маркировки в эталоне, экспорт использует техническое обозначение КСК/<номер физического канала>. Благодаря этому строка остаётся допустимой для текущего CSV-импортера.

Обрывы не экспортируются как существующие связи: если соединение отсутствует в измеренной схеме, создавать для него строку в импортируемом эталоне нельзя. Паразитные и асимметричные пары, которые физически обнаружены, сохраняются и отмечаются в «Примечании».

5. Хранилище и журналы

В блоке «Хранилище» отображается заполнение файловой системы и журнал проверок.

Журнал проверок

Доступны фильтры по дате, прибору и проверяющему, а также сортировка по дате или итоговому результату. На странице выводится до 20 записей.

  • Открыть — показать отчёт;
  • Экспорт CSV — выгрузить измеренную схему в формате импорта эталона;
  • Выгрузить — скачать исходный JSON;
  • Удалить — только при включённом сервисном режиме.

Кнопка «Выгрузить CSV», которую JavaScript добавляет над журналом, экспортирует сводный журнал проверок. Это другой CSV: он предназначен для анализа истории, а не для импорта эталона.

Журнал эталонов

JavaScript динамически создаёт отдельный журнал эталонов с датой, названием, сборкой, ревизией, прибором, оператором и статусом. Доступны открытие, выгрузка, сортировка, экспорт списка в CSV и сервисное удаление.

6. Дата, время и DS3231

В текущей прошивке используется RTC DS3231. При запуске прошивка пытается прочитать RTC и установить системные часы ESP32.

При создании эталона или запуске проверки сервер сначала использует синхронизированные системные часы. Если они недоступны, запрос содержит резервное время браузера.

Кнопка «Синхронизировать с браузером»

  1. Проверьте часы компьютера.
  2. Нажмите кнопку синхронизации.
  3. Браузер передаст Unix-время, смещение UTC и часовой пояс.
  4. ESP32 обновит системные часы и запишет время в DS3231, если RTC доступен.

Под кнопкой отображаются локальное время, UTC и часовой пояс последней синхронизации.

7. Сервисный режим

Сервисный вход защищает операции, изменяющие базу прибора. В текущей конфигурации это GPIO40, активный низким уровнем.

Без сервисного режима

  • обычная проверка кабеля;
  • просмотр эталонов и результатов;
  • журналы и фильтры;
  • выгрузка файлов;
  • печать;
  • экспорт CSV;
  • ручная диагностика канала.

Сервисный режим требуется

  • для автоматического создания эталона;
  • для сохранения ручного эталона;
  • для импорта CSV в конструктор;
  • для загрузки файлов в прибор;
  • для удаления эталонов и результатов.

При выключенном сервисном режиме app.js скрывает кнопки создания, загрузки и перехода в админку. На админ-странице показывается отдельный статус сервисного доступа.

8. Автоматическое создание эталона v3

  1. Подключите заведомо исправную кабельную сборку.
  2. Включите сервисный режим.
  3. Откройте форму «Создать эталон v3».
  4. Заполните название, тип сборки, ревизию, прибор и оператора.
  5. При необходимости укажите CRC32 таблицы соединений — до 8 hex-символов.
  6. Выберите статус: Черновик, На утверждении, Утверждён, Отклонён или Архивный.
  7. Добавьте комментарий при необходимости.
  8. Запустите эталонный замер и дождитесь сохранения.
Не создавайте эталон по неисправной сборке: обнаруженная в ней схема станет ожидаемой схемой для последующих проверок.

9. Админ-страница и ручной конструктор

Админ-страница позволяет создавать эталон физическим замером либо вручную по известной таблице соединений.

Ручная связь

Для каждой пары задаются каналы прибора 1..1024, провод, Жгут A, Контакт A, Жгут B, Контакт B и примечание. Пары можно вводить полями или выбирать на графической сетке.

Импорт CSV

Конструктор принимает CSV, TSV или файл с запятыми; разделитель определяется автоматически. Логический формат:

Провод;Позиция;Маркировка;Контакт;Маркировка;Контакт;Примечание
W-01;1;X15;3;X20;30;основной провод

Для каждого конца обязательны поля Маркировка и Контакт. Уникальным логическим концам автоматически назначаются внутренние физические номера конструктора.

Сохранение ручного эталона

admin.js формирует двустороннюю матрицу 1024×1024, рассчитывает CRC32, выполняет RLE-сжатие, добавляет annotations с проводами и маркировкой и собирает файл .ref v3. Если открыт существующий эталон, можно перезаписать его или сохранить как новый.

10. OLED, энкодер и сеть

OLED показывает Ethernet LINK, текущий IP, DHCP/STATIC, состояние теста и прогресс. Нажатие кнопки энкодера открывает сетевое меню.

11. Ручная проверка канала

В поле Source pin вводится внутренний номер 0..1023. После нажатия «Проверить pin → 1024» прибор:

  1. считывает фоновые LOW;
  2. опускает выбранный источник в LOW;
  3. считывает все 1024 линии;
  4. показывает найденные связанные контакты;
  5. освобождает источник и проверяет его возврат в HIGH.

Режим предназначен для наладки, поиска неправильной разводки и аппаратных неисправностей.
