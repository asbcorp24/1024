# Устройство контроля целостности кабельных сборок — 1024 канала

Проект для **ESP32-S3 N16R8**, PlatformIO и Arduino Framework.

Аппаратная матрица состоит из 64 расширителей **MCP23017**:

- 8 направлений через TCA9548A;
- по 8 MCP23017 в каждом направлении;
- адреса MCP23017 в каждой ветви: `0x20…0x27`;
- 16 GPIO на модуль;
- всего 1024 тестовых контакта.

## Асинхронная архитектура

- W5500 работает через системный драйвер `ETH` ESP32;
- HTTP работает на `AsyncTCP` и `ESPAsyncWebServer`;
- состояние передаётся браузеру через SSE `/api/events`;
- измерение, анализ и сохранение выполняются в отдельной FreeRTOS-задаче;
- HTML, JavaScript и CSS отдаются из LittleFS;
- эталоны и результаты потоково читаются и записываются в FFat;
- основной `loop()` не обслуживает HTTP и не выполняет измерения.

## Источник даты и времени

Дата и время всегда берутся из браузера в момент запуска эталона или испытания.

Браузер передаёт:

- Unix-время в миллисекундах через `Date.now()`;
- смещение относительно UTC;
- IANA-часовой пояс из `Intl.DateTimeFormat().resolvedOptions().timeZone`.

ESP32 не использует NTP и не считает `millis()` календарной датой. Время окончания испытания вычисляется как браузерное время начала плюс фактическая монотонная длительность измерения.

## Реализовано

- инициализация 64 MCP23017 без сторонней библиотеки;
- чтение `GPIOA + GPIOB` одной I2C-транзакцией;
- I2C 400 кГц;
- полный перебор 1024 источников `OUTPUT LOW`;
- битовая матрица 1024×1024 размером 128 КиБ в PSRAM;
- поиск обрывов, паразитных связей, асимметрий и постоянно низких линий;
- эталоны `.ref` формата v2 с паспортом и CRC32;
- результаты `.bin` и `.json`;
- загрузка и выгрузка эталонов, отчётов и матриц;
- проверка заголовка, версии, размера и CRC загружаемого эталона;
- отображение метаданных эталона в веб-интерфейсе.

## Формат эталона v2

Файл `.ref` является самодостаточным и содержит:

1. фиксированный `ReferenceFileHeader` v2;
2. битовую матрицу 1024×1024 размером 131072 байта.

Заголовок хранит:

- название эталона;
- тип кабельной сборки;
- ревизию;
- реальное Unix-время создания из браузера;
- смещение UTC и часовой пояс;
- идентификатор прибора;
- модель прибора;
- версию прошивки;
- оператора;
- CRC32 таблицы соединений;
- CRC32 матрицы;
- комментарий;
- статус утверждения;
- число каналов и размеры матрицы.

Поддерживаемые статусы:

- `draft` — черновик;
- `pending` — на утверждении;
- `approved` — утверждён;
- `rejected` — отклонён;
- `archived` — архивный.

Поле старого формата `createdAtMs`, содержавшее `millis()`, заменено на `createdAtEpochMs`. Версия формата поднята с `1` до `2`. Файлы v1 намеренно считаются несовместимыми и не допускаются к испытаниям.

`mappingCrc32 = 0` означает, что таблица соединений пока не была импортирована. После реализации импорта CRC будет рассчитываться автоматически, а не вводиться вручную.

Бит `matrix[source][target] = 1` означает, что при переводе `source` в LOW контакт `target` прочитан как LOW. Диагональные биты очищаются.

## Метаданные в результате испытания

JSON-отчёт содержит копию паспорта выбранного эталона:

- название, тип и ревизию;
- прибор и оператора создания эталона;
- статус утверждения;
- комментарий;
- дату создания;
- CRC таблицы и эталонной матрицы.

Также сохраняются время начала и окончания испытания в UTC и локальном формате, часовой пояс браузера и CRC измеренной матрицы.

## Проверка загружаемых файлов

### Эталон `.ref`

Перед сохранением проверяются:

1. `magic`;
2. версия v2;
3. размер заголовка;
4. число каналов;
5. размер строки и матрицы;
6. Unix-время создания;
7. полный размер файла;
8. CRC32 матрицы.

Файл сначала записывается как `.upload` и только после успешной проверки атомарно переименовывается в рабочий `.ref`.

### Расчёты

- `.bin` принимается только при размере 131072 байта;
- `.json` должен быть корректным JSON-объектом;
- максимальный размер JSON — 1 МиБ;
- незавершённые временные загрузки удаляются при запуске устройства.

## Адрес контакта

```text
DDD AAA PPPP
```

- `DDD` — направление TCA9548A, 0…7;
- `AAA` — номер адреса MCP23017, 0…7;
- `PPPP` — GPIO, 0…15.

```cpp
globalPin = (direction << 7) | (module << 4) | pin;
```

## Пины по умолчанию

### I2C

| Сигнал | ESP32-S3 |
|---|---:|
| SDA | GPIO8 |
| SCL | GPIO9 |
| RESET TCA9548A | GPIO4 |

### W5500

| Сигнал | ESP32-S3 |
|---|---:|
| MOSI | GPIO11 |
| SCK | GPIO12 |
| MISO | GPIO13 |
| CS | GPIO10 |
| RESET | GPIO14 |
| INT | GPIO15 |

Назначения находятся в `include/AppConfig.h`.

## Сборка и загрузка

```bash
pio run
pio run -t upload
pio run -t uploadfs
pio device monitor
```

После DHCP IP-адрес выводится в Serial Monitor. При отключённом DHCP используется `192.168.1.204`.

## Разделы flash 16 МБ

- два OTA-раздела приложения по 3 МиБ;
- LittleFS 2 МиБ — HTML, JavaScript и CSS;
- FFat около 8 МиБ — эталоны, матрицы и отчёты;
- coredump 128 КиБ.

Один эталон занимает 131072 байта плюс заголовок v2. Одно испытание создаёт матрицу `.bin` размером 131072 байта и JSON-отчёт.

## HTTP API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/device` | Ethernet, IP, модель и версия формата |
| GET | `/api/status` | текущее состояние испытания |
| GET/SSE | `/api/events` | события состояния и файлов |
| GET | `/api/references` | список эталонов с паспортами v2 |
| GET | `/api/calculations` | список JSON-отчётов и BIN-матриц |
| POST | `/api/reference/capture?...` | создать эталон v2 |
| POST | `/api/test/start?...` | запустить проверку |
| POST multipart | `/api/upload/reference` | загрузить и проверить `.ref v2` |
| POST multipart | `/api/upload/calculation` | загрузить `.json` или `.bin` |
| GET | `/api/result?file=result.json` | открыть JSON-отчёт |
| GET | `/api/download?type=reference&file=...` | выгрузить эталон |
| GET | `/api/download?type=calculation&file=...` | выгрузить отчёт или матрицу |

Параметры создания эталона:

```text
name
cableType
revision
deviceId
operator
mappingCrc32
approvalStatus
comment
epochMs
offsetMinutes
timeZone
```

## Важные аппаратные требования

- MCP23017 и TCA9548A работают от 3,3 В вместе с ESP32-S3;
- на основной I2C-шине и каждой ветви нужны рассчитанные подтяжки;
- на каждом MCP23017 нужен блокировочный конденсатор 100 нФ;
- OLAT всех MCP23017 предварительно устанавливается в 0;
- одновременно открыт только один канал TCA9548A;
- перед испытаниями необходимо проверить фронты SDA/SCL осциллографом на 400 кГц.
